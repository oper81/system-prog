# Движок скидок (Discount Engine)

Практическая работа по ООП и паттернам проектирования: расширяемый механизм расчёта скидок с подробным breakdown.

## Требования

- **Node.js 18+** (используется встроенный тест-раннер `node:test`).
- Никаких внешних зависимостей — только стандартная библиотека.

Проверить версию:

```bash
node --version
```

## Схема классов

```
              ┌───────────────────────────┐
              │        Discount           │  (абстракция)
              │  + name                   │
              │  + apply(ctx) → Applied.. │
              └────────────┬──────────────┘
                           │
   ┌───────────┬───────────┼───────────┬─────────────┬──────────────┬───────────────┐
   │           │           │           │             │              │               │
PercentDiscount FixedDiscount ThreeForTwo PromoCodeDiscount LoyaltyDiscount FreeDelivery FirstOrder
   │           │           │           │             │              │               │
   └───────────┴───────────┴───────────┴─────────────┴──────────────┴───────────────┘
                                       │
                                       ▼
              ┌───────────────────────────┐        ┌──────────────────────┐
              │   DiscountRegistry        │◄───────│  DiscountFactory     │
              │   (Singleton)             │        │  create(type, cfg)   │
              │   register(type, fn)      │        │  createMany(cfgs)    │
              └───────────────────────────┘        └──────────────────────┘

              ┌───────────────────────────┐
              │   ConfigProvider          │  (Singleton, только данные,
              │   setDiscounts / setPromos│   без состояния заказа)
              └───────────────────────────┘

              ┌───────────────────────────┐        ┌──────────────────────┐
              │   PricingEngine           │───────►│  DiscountContext     │
              │   calculate(order)        │        │  itemsTotal,         │
              │   (знает только Discount) │        │  deliveryCost,       │
              └───────────────────────────┘        │  appliedDiscounts,   │
                                                   │  promoCode/applied   │
                                                   └──────────────────────┘
```

## Архитектурные решения

| Требование | Реализация |
|---|---|
| **Абстракция скидки** | Класс `Discount` с полем `name` и методом `apply(ctx)`, возвращающим `AppliedDiscount` или `null`. |
| **Стратегия** | 7 отдельных классов-наследников, по одному на тип скидки. |
| **Фабрика** | `DiscountFactory.create(type, config)` и `createMany(configs)`. Разбор `type` — только здесь и в реестре. |
| **Синглтон** | `DiscountRegistry.getInstance()` (реестр создателей) и `ConfigProvider.getInstance()` (конфигурация). **Не хранят** состояние заказа. |
| **Инкапсуляция** | `PricingEngine` работает только с абстракцией `Discount` и с `DiscountContext`. |
| **Полиморфизм** | Единый вызов `discount.apply(ctx)` — без `if (type === ...)` в движке. |

## Порядок применения скидок

Строго в этом порядке на каждом заказе:

1. **«3 по цене 2»** — сначала, потому что это количественная скидка.
2. **Процентные:**
   - Сравниваем **лучшую обычную процентную** скидку из конфигурации и **процентный промокод** — на одной и той же текущей сумме.
   - Побеждает вариант с **большей денежной выгодой**.
   - **При равенстве — выигрывает промокод.**
   - Затем применяются остальные обычные процентные скидки, **лояльность** и **первый заказ** — в порядке конфигурации.
3. **Фиксированные:**
   - Сначала обычные фиксированные из конфигурации (в порядке конфигурации).
   - Затем **фиксированный промокод** (он не конфликтует с процентными).
4. **Бесплатная доставка** — в самом конце, после всех денежных скидок.

Каждая следующая скидка считается от **уже уменьшенной** суммы.

## Округление

- Каждый денежный результат округляется **банковским методом (round half to even) до копеек**.
- Внутри вычисления идут в целых копейках (`roundMoney` в `src/money.js`).
- Момент округления: **каждый раз, когда стратегия рассчитывает `amount`**, и при вычислении `finalTotal`.
- Примеры:
  - `2.5  → 2` (чётное)
  - `3.5  → 4` (чётное)
  - `0.125 → 0.12`
  - `0.135 → 0.14`

## Промокоды

- **Сравнение кодов:** точное строковое равенство (`===`), **регистрозависимое**. Код `SUMMER15` ≠ `summer15`.
- **Срок действия:** `validUntil` включителен — код действует **до конца указанного дня** (23:59:59.999). Сравниваем с `order.createdAt`.
- **Активность:** если `active = false`, промокод не применяется.
- **Одноразовость:** промокод применяется **не более одного раза в рамках одного расчёта**. Флаг `appliedPromo` в контексте.
- **Неизвестный / неактивный / просроченный код** — не применяется, в breakdown **не попадает**.
- **Процентный промокод** участвует в конфликте с обычной процентной скидкой (см. порядок выше).
- **Фиксированный промокод** не конфликтует с процентными и применяется на этапе фиксированных скидок.

## Breakdown

`PricingResult` содержит:

```json
{
  "baseTotal": 5000.00,
  "appliedDiscounts": [
    {
      "name": "3 по цене 2",
      "amount": 1000.00,
      "reason": "Категория Книги: 3 единиц, 1 бесплатно"
    },
    {
      "name": "Лояльность",
      "amount": 200.00,
      "reason": "Последняя покупка была не более 30 дней назад"
    }
  ],
  "finalTotal": 3800.00
}
```

- **Только реально применённые скидки** — с `amount > 0`.
- **Порядок записей** совпадает с порядком расчёта.
- `baseTotal = Σ(basePrice × quantity) + deliveryCost` (до скидок).
- `finalTotal = itemsTotal + deliveryCost` (после всех правил), ≥ 0.
- Для бесплатной доставки `amount` = прежняя стоимость доставки.

## Обработка некорректного ввода

- `quantity ≤ 0` → `CartItem` бросает исключение.
- `basePrice < 0`, `deliveryCost < 0` → соответствующая модель бросает исключение.
- Отсутствие обязательных полей (`id`, `customer`, `items`, `product`) → исключение.
- Процент вне `[0; 100]` → исключение.
- `percent / fixed` со значением `< 0` → исключение.
- Скидка **не может превысить** текущую соответствующую часть заказа: `reduceItems` / `reduceDelivery` обрезают `amount`.
- Итоговая цена **не может стать меньше 0**.
- **Пустая корзина** допустима: `baseTotal = deliveryCost`, `finalTotal = deliveryCost`, `appliedDiscounts = []`.

## Как добавить новый тип скидки

1. Создайте класс-наследник `Discount` в `src/discounts.js`:

```js
class MyDiscount extends Discount {
  constructor({ name }) { super(); this._name = name; }
  get name() { return this._name; }
  apply(ctx) {
    // ... вернуть AppliedDiscount или null
  }
}
```

2. Зарегистрируйте фабрику в `src/registry.js`:

```js
registry.register('myType', cfg => new MyDiscount(cfg));
```

3. Передайте в конфигурацию `{ type: 'myType', name: '...' }`.

`PricingEngine` **не меняется**.

## Конфигурация (пример)

```js
const cfg = ConfigProvider.getInstance();

cfg.setDiscounts([
  { type: 'percent',      value: 10, name: 'Осенняя распродажа' },
  { type: 'fixed',        value: 500, threshold: 3000, name: '500 рублей от 3000' },
  { type: 'threeForTwo',  category: 'Книги', name: '3 по цене 2' },
  { type: 'loyalty',      percent: 5, days: 30, name: 'Лояльность' },
  { type: 'freeDelivery', threshold: 5000, name: 'Бесплатная доставка' },
  { type: 'firstOrder',   percent: 10, name: 'Первый заказ' },
]);

cfg.setPromos([
  { type: 'promo', code: 'SUMMER15', kind: 'percent', value: 15, validUntil: '2026-12-31', active: true },
]);

const discounts = DiscountFactory.createMany(cfg.getDiscounts());
const engine = new PricingEngine(discounts);
const result = engine.calculate(order);
```

## Тесты

### Обязательные сценарии (покрыты)

- **Каждая стратегия:** позитивный сценарий + сценарий, где скидка не применяется.
- **3 по цене 2 + процент:** количественная скидка первой, процент считается от остатка.
- **Промокод + процент:** выбирается большая выгода; при равенстве — промокод.
- **Нижняя граница:** большая фиксированная скидка не уводит сумму ниже нуля.
- **Округление:** half to even на ровной половине копейки.
- **Границы:**
  - порог фиксированной скидки,
  - ровно 30 дней лояльности,
  - дата окончания промокода (включительно),
  - строгое условие `itemsTotal > threshold` для бесплатной доставки.
- **Breakdown:** названия, суммы, причины, порядок записей.

### Дополнительные сценарии (покрыты)

- Несколько товаров одной категории с разными ценами для «3 по цене 2».
- Пустая корзина.
- Неизвестный и просроченный промокод.
- Сочетание всех совместимых скидок.
